# Contributing

Start with [team setup](docs/TEAM_SETUP.md). Visitors remain anonymous; administrative endpoints require ADMIN access. Keep API keys, passwords, signing keys, local database backups and visitor records out of Git.

Use a feature branch and open a pull request. Commit messages must be in English, with a clear prefix such as `feat:`, `fix:`, `docs:` or `chore:`. Commit source files and dependency lockfiles together. Keep generated Android/iOS projects, build output and dependency folders untracked; persistent native fixes belong in Expo plugins or installation scripts.

Run the relevant checks in the team guide before requesting review. Explain the resulting behavior and any known limits. Share published demo content through the reviewed fixture, never by committing a private database dump or `.env` file. Preserve existing collaborator edits when updating local data.
